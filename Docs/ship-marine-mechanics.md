# Морская механика кораблей (порт из nikes)

Серверная физика кораблей, портированная из репозитория nikes 1.2 в проект AAEmu 5.0.7.0. Система заменяет старое клиентское управление движением кораблей на полностью серверно-авторитетную симуляцию твёрдых тел.

---

## 1. Обзор

Корабли симулируются как твёрдые тела на сервере с использованием физического движка **Jitter2**. Каждый заспавненный корабль (`Slave` с `IsABoat()`) получает `ShipController`, который строит прямоугольный корпус из данных БД `ship_models`, применяет силы тяги/руления каждый тик и рассылает обновления позиции через `SCOneUnitMovementPacket`. Физический поток работает независимо от игрового тика, обеспечивая плавное движение с плавучестью, ветром, посадкой на мель и обработкой столкновений.

---

## 2. Архитектура

### Физический поток

`PhysicsManager` (`Core/Managers/World/PhysicsManager.cs`) работает в выделенном потоке для каждого экземпляра мира. Цикл:

1. Обрабатывает очередь `ConcurrentQueue<Action>` с отложенными операциями добавления/удаления тел.
2. Шагает мир Jitter2 с фиксированным временным шагом, определяемым `TargetPhysicsTps` (по умолчанию 25 Гц, настраивается в `World.json`). До 4 шагов наверстывания за кадр для предотвращения отставания.
3. Для каждого активного тела корабля: кеширует высоту воды/рельефа, применяет силы речного течения, синхронизирует `Transform`, выполняет `BoatPhysicsTick` (сглаживает тягу/руление из клиентского ввода), вызывает `ShipController.ApplyForceAndTorque` и отправляет пакеты движения.
4. Запускает обработчики взаимодействий в порядке: берег, корабль-корабль, скалы, дудады, статические барьеры.
5. Обновляет аккумуляторы урона корпуса от посадки на мель и контакта со статическими препятствиями.

### ShipController

`Physics/ShipController.cs` — по одному на корабль. Обязанности:

- **Build**: создаёт `RigidBody` с `BoxShape` + `TransformedShape` из размеров массового бокса `ship_models` и смещения центра. Устанавливает массу из БД.
- **ApplyForceAndTorque**: вызывается каждый физический кадр. Вычисляет ускорение тяги, скорость рысканья руля, множитель ветра, логику выхода с мели и записывает результирующую скорость и угловую скорость в твёрдое тело. Использует константы `ShipMotionDefaults` для всех настроек.

### Плавучесть

`Physics/Forces/Buoyancy.cs` — генератор сил Jitter2. Разбивает ограничивающий объём корпуса на точки выборки. Каждая погружённая точка создаёт восходящую силу плавучести, пропорциональную глубине, массе тела и плотности воды (`BaseWaterDensity = 1.025`, множитель для кораблей `ShipWaterDensityMul = 3`). Также применяет линейное сопротивление, пропорциональное площади поперечного сечения корпуса.

Обнаружение поверхности воды делегируется методам `IsWater()` и `GetWaterSurface()` мира, поддерживая реки и неокеанические водоёмы.

## 3. Система ветра

Ветер влияет на максимальную скорость парусных кораблей. Модель выбирается через `WindModel` в `World.json`.

### Официальный режим (`WindModel: "Official"`)

Постоянная ось ветра север-юг `(0, 1)`, которая не меняется со временем. Применяется только к парусникам (`SmallSailingShip`, `BigSailingShip`, `Fishboat`). Даёт бонус **+15% к максимальной скорости**, когда нос корабля находится в пределах ±15 градусов от оси С-Ю (в любом направлении). Нет штрафа за плавание против ветра. Соответствует поведению на официальных серверах.

### Реалистичный режим (`WindModel: "Realistic"`)

Направление ветра плавно вращается в течение 24-часового игрового цикла (полночь = север, полдень = юг, 6:00/18:00 = боковой ветер). Фазовое смещение настраивается через `WindTimePhaseOffsetHours`.

Корабли используют один из трёх ветровых профилей на основе `SlaveKind`:

| Профиль | Типы кораблей | Лучший угол |
|---|---|---|
| **None** | Boat, Fishboat, Leviathan | Нет влияния ветра |
| **SquareRig** | BigSailingShip, SmallSailingShip | По ветру (попутный) |
| **LateenRig** | MerchantShip, Speedboat | Галфвинд (перпендикулярно) |

Множитель скорости варьируется от `WindAgainstMaxMul` (0.85) до `WindWithMaxMul` (1.15) в зависимости от угла между носом и ветром, в пределах конуса 15 градусов.

Речное течение (`CachedWaterFlow`) перезаписывает направление ветра открытого моря при его наличии.

## 4. Взаимодействия кораблей

Все обработчики запускаются каждый физический тик после `ShipController.ApplyForceAndTorque`. Они используют общий метод XZ OBB (Oriented Bounding Box) SAT (Separating Axis Theorem) для определения перекрытия.

### ShipShoreInteraction (`Physics/ShipShoreInteraction.cs`)

Корабль vs берег/рельеф:

- **Фиксация контакта с землёй**: проверяет высоту рельефа у носа или кормы (в зависимости от направления движения). Использует полосы гистерезиса (`ShoreEnterHyst` / `ShoreExitHyst`) для предотвращения дрожания на линии воды.
- **Разрешение проникновения**: когда дно корпуса ниже рельефа, выталкивает тело вверх с ограниченной скоростью (макс. 0.04-0.07 м/тик). Отменяет гравитацию на мели.
- **Физика на суше**: применяет трение о землю, затухание скорости/вращения. Сбрасывает управление при полной остановке.
- **Выход с мели**: асимметричные множители тяги позволяют игрокам задним ходом сойти с мели. Нарастающий ассист строится за ~1.2 секунды застревания, повышая скорость выхода до `GroundEscapeMaxSpeedAbs` (1.5 м/с).
- **Урон корпусу**: периодический урон HP накапливается при нахождении на мели (`TickBeachedHullDamage`).
- **Визуальный наклон на грунте**: сэмплирует уклон рельефа вдоль оси носа и применяет сглаженный угол наклона (макс. 8 градусов) только для клиентских визуалов.

### ShipShipInteraction (`Physics/ShipShipInteraction.cs`)

Столкновение корабль-корабль:

- **Широкая фаза**: перекрытие мировых AABB по XZ + минимальное вертикальное перекрытие (0.12 м).
- **Узкая фаза**: 2D SAT по XZ с использованием увеличенных OBB масс-боксов. До 12 итераций на пару, 2 прохода по всем парам.
- **Отклик**: массово-взвешенное разделение позиций вдоль оси минимального проникновения. Скорость сближения полностью гасится; касательное скольжение частично убирается (86%). Сила разделения масштабируется `MassPushStrength` (2.0) для усиления влияния разницы масс.
- **Урон корпусу**: масштабируемый по скорости периодический урон (1-10% макс. HP) с кулдауном 1.5 секунды на пару. Удары носовым конусом (контакт носа) получают минимальный урон (1%).
- **Исключение гарпуна**: если два корпуса связаны гарпунным канатом, затухание скорости пропускается для координированного буксирного движения.

### ShipCliffInteraction (`Physics/ShipCliffInteraction.cs`)

Корабль vs крутые скалы:

- Вычисляет градиент рельефа методом центральных разностей (шаг 3.25 м). Срабатывает при величине градиента > 1.05 (крутой склон).
- Идёт вверх по склону, чтобы найти первую точку, где рельеф выше локальной поверхности воды.
- Размещает виртуальную стену у выступающей скалы. Разрешает перекрытие тем же методом SAT + разделение.
- Частичное затухание скорости (14% сближения, 97% касательного скольжения сохраняется) — мягче, чем корабль-корабль, чтобы избежать упругих отскоков от скал.

### ShipDoodadInteraction (`Physics/ShipDoodadInteraction.cs`)

Корабль vs статические дудады (причалы, портовые конструкции):

- Запрашивает ближайшие дудады через `WorldManager.GetAround<Doodad>`. Обрабатывает только дудады с `CollideShip = true` и `NoCollision = false`.
- Размер препятствия определяется из `SimRadius` (БД, в сантиметрах) или по умолчанию 3.5 м.
- Рассматриваются как бесконечная масса (двигается только корабль). SAT перекрытие с OBB дудада.
- Полная отмена скорости сближения, 82% затухание касательного скольжения.

### ShipStaticBarrierInteraction (`Physics/ShipStaticBarrierInteraction.cs`)

Корабль vs полилинейные барьеры из BAI-данных:

- Барьеры определяются как сегменты полилиний с настраиваемой полутолщиной и диапазоном Z (высоты). Хранятся в `ShipStaticBarrierZones` на мир, индексированы `ShipStaticBarrierSpatialGrid` для широкой фазы.
- Каждый сегмент становится тонким статическим OBB в XZ. SAT + разделение как с дудадами.
- **Перекрытия мостов**: тонкие Z-плиты (<=2 м толщины) обрабатываются как верхние барьеры с полным затуханием скорости сближения и усиленным удержанием репликации (24 тика vs 8).
- Разделение ограничено бюджетом на корабль за тик (макс. 0.22 м всего) для предотвращения выброса в узких углах.
- Фильтрация по ключу зоны: барьеры могут быть ограничены конкретным `ZoneId`.

## 5. Гарпунная механика

### ShipHarpoonRopeController (`Models/Game/Skills/SkillControllers/ShipHarpoonRopeController.cs`)

Управление жизненным циклом гарпунного каната:

- **Запуск** (`OnLaunchSucceeded`): определяет позицию крюка из цели каста (мировая точка или локальное смещение на объекте-основе). Устанавливает начальную длину каната как расстояние между пушкой и крюком. Определяет, зацеплен ли крюк за рельеф (включает буксировку) или за другой корпус корабля.
- **Синхронизация клиента**: `TryApplySkillControllerState` обрабатывает пакеты `CSSkillControllerState`. Длина каната ограничивается для предотвращения подмены значений.
- **Истечение каната**: использует таймер из БД `skill_controllers` (минимум из value1/value2 в миллисекундах) для автоматического разрыва каната при истечении времени контроллера.
- **Разрыв от натяжения**: `TickTensionTearAndGetHullRecoilDeltaV` выполняется каждый физический тик. Разрывает канат при растяжении > 3 м (постоянное натяжение) или рывке > 9 м/с (внезапный пик, требует минимум 1 м растяжения). Применяет дельту отдачи к корпусу стрелка (макс. 1.6 м/с).
- **Обрезка каната**: `OnCutRope` (скилл 13750) или выход оператора из кресла разрывает канат и рассылает `SCSkillControllerState` с `teared=true`.

### ShipHarpoonTowPhysics (`Physics/ShipHarpoonTowPhysics.cs`)

Применяет силы буксировки при натянутом гарпунном канате:

- **Буксировка к рельефу** (`ApplyTerrainHookTow`): когда крюк на суше и расстояние пушка-крюк превышает оплаченную длину каната + запас (0.5 м), ускоряет корпус к крюку до 2 м/с² на метр растяжения. Также применяет ассист рысканья носа (0.3 рад/с) для поворота в направлении тяги.
- **Парная буксировка** (`ApplyShipPairHarpoonTowImpulses`): когда два корпуса связаны гарпуном (явная основа или ближайший корпус в 45 м), применяет массово-взвешенные импульсы сближения к обоим корпусам. Доминирование использует `масса * (1 + 0.04 * скорость)`. Оба корпуса получают ассист рысканья, масштабированный по приведённой массе пары.
- **Определение слабины**: оплаченная длина каната включает серверную добавку 12.5 м (`ServerRopePaidLengthAdditiveMeters`). Парная буксировка использует дополнительный запас 22 м.
- **Подавление ползучести**: пока гарпунная линия натянута, минимальная скорость ползучести (±1) корпуса отключается для предотвращения движения против якоря.

## 6. Визуальные эффекты

Влияют только на реплицированное вращение, отправляемое клиентам, не на физическое твёрдое тело.

### Угол крена (наклон в поворотах)

Вычисляется в `PhysicsManager.SendUpdatedMovementData`. Максимальный угол крена определяется из размеров масс-бокса `ship_models` и массы (диапазон 5-14 градусов). Масштабируется по горизонтальной скорости и скорости рысканья. Сглаживается с коэффициентом отклика 7.5.

### Качание на волнах

`ComputeVisualWavePitchOnWater` применяет синусоидальный наклон на открытой воде. Амплитуда и частота определяются из длины корпуса и массы (длинные/тяжёлые корабли качаются меньше и медленнее). Фаза индивидуальна для каждого корабля (смещение по `ObjId`) для избежания синхронного качания. Активно только при погружении; отключается на грунте.

### Наклон на грунте

`UpdateVisualGroundPitch` сэмплирует высоту рельефа в контрольных точках перед и за корпусом (шаг 6 м). Вычисляет угол уклона, ограниченный ±8 градусов. Двойное сглаживание (сэмплы пола + итоговый наклон) для уменьшения дрожания.

### Сглаживание репликации

Класс `ReplicationSmoothing` применяет экспоненциальный фильтр нижних частот к позиции, скорости, крену и наклону перед сборкой пакета. Использует разные значения лямбда для свободного движения и состояния контакта (мягче при столкновениях для маскировки коррекций перекрытия). Счётчик удержания контакта (8-24 тика) продлевает окно мягкого сглаживания после столкновения.

## 8. GM-команды

### `/shipbarrier` (алиас `/sb`)

Управление статическими барьерами из BAI-данных. Требует `GeoDataMode = true`.

- `status` — выводит количество барьеров и загруженных ячеек для текущего мира.
- `reset world [ingest]` — очищает все барьеры и кеш загруженных ячеек. С `ingest` — сразу загружает текущую ячейку персонажа и 8 соседних.
- `reset cell [ingest]` — аналогично `reset world`, с опциональной немедленной загрузкой.

### `/waterdebug` (алиас `/water_debug`)

Отладка водных зон из клиентских `object.dat`.

- `reload` — перестраивает `Water.Areas` из загруженных ячеек. Выводит количество клиентских водных объёмов по типам (River, Area, Ocean, Sector) и серверных загруженных зон.
- `info [x y z]` — снимок состояния воды на позиции персонажа или по указанным координатам.
- `reloadinfo [x y z]` — перезагрузка + info.
- `setprobe x y z` — включает непрерывное логирование автозонда в мировой точке.
- `probeoff` — выключает автозонд.
