# Транспортные топливные скиллы 20291, 27032, 35166 и 27446

Дата: 2026-04-27

## Кратко по логу

Текущий `AAEmu.Game/bin/Debug/net10.0/Logs/Server.log` показывает, что оба скилла трактора кастуются объектом трактора, а не персонажем:

- объект игрока: `268`
- объект трактора/`Slave`: `269`
- `27032`: `StartSkill: Id 27032, flag 0, caster=269, target=269`
- `35166`: `StartSkill: Id 35166, flag 0, caster=269, target=269`

Строка `PET SKILL` в логе здесь вводит в заблуждение. В `CSStartSkillPacket` эта ветка обрабатывает любой контролируемый юнит, у которого объект кастера отличается от объекта игрока. В этом случае кастер, найденный через `world.GetBaseUnit(skillCaster.ObjId)`, является `Slave`-трактором.

## Почему 35166 работал

У скилла `35166` уже была полная цепочка применения эффекта:

```text
skills.id=35166
  -> skill_effects.effect_id=60581
  -> effects.actual_type=BuffEffect, actual_id=21524
  -> buff_effects.buff_id=20584
  -> buffs.id=20584, slave_applicable=1
```

Это совпадает с логом:

```text
SCSkillFiredPacket - Id 35166, Caster 269, Target 269
SCBuffCreatedPacket - (269) - Red Farm Hauler <- 20584
```

## Отсутствующие эффекты транспорта

`27032` был назначен как mount skill для Red Farm Hauler, но у него не было строки в `skill_effects`. Поэтому сервер успешно отправлял `SCSkillFired` и `SCSkillEnded`, но `Skill.ApplyEffects` не имел эффекта для применения.

Расширенная проверка базы нашла такую же проблему еще в двух прямых транспортных скиллах движения:

- `20291` (`새 아침의 첫 바퀴`) используется обычной линейкой тракторов и по описанию должен давать 8 минут +50% к скорости движения. Теперь он связан с существующим баффом `4841`.
- `27032` (`붉은 소의 힘찬 바퀴`) используется линейкой Red Farm Hauler и по описанию должен давать 10 минут +50% к скорости движения. Теперь он связан с существующим баффом `8335`.
- `27446` (`노 장치 밀기`) используется компонентом-веслом и по описанию должен увеличивать скорость родительского корабля. Теперь он связан с существующим баффом `11388` через применение `Target`, потому что у скилла `TargetType=Parent`.

`35166` (`첨가제 투입`) уже был связан с баффом `20584`; его цепочка оставлена как есть.

Другие найденные транспортные скиллы, потребляющие топливо, уже имели эффекты: например, автомобильные прыжки/ускорения и корабельные engine skills. `29254` не изменялся: это боевой удар носовой фигуры с уроном и замедлением, а не прямой бафф движения транспорта, поэтому для него нет безопасного соответствия один-к-одному.

Если проверять без перезапуска, в логе будет виден `SCSkillFiredPacket` и `SCSkillEndedPacket`, но не будет `SCBuffCreatedPacket` для только что добавленных связей.

## Продление времени

Подсказка скиллов говорит, что повторная заливка топлива или органической добавки увеличивает срок действия эффекта. В базе это задано через `buffs.stack_rule_id=5`, что соответствует `BuffStackRule.Extend`.

### Исправление логики Extend (2026-04-27)

В коде была ошибка: обработка `Extend` выбирала существующий бафф только если его оставшееся время было меньше новой базовой длительности. Это поведение похоже на refresh, но для `Extend` нужно всегда брать текущий бафф при `max_stack=1` и выставлять новую длительность как `оставшееся время + новая длительность`.

Исправление в `Buffs.HandleStacking` разделяет результаты стекинга на `Added`, `Overwritten` и `Rejected`. Это также не даёт откатывать активные модификаторы после успешного продления. `Buff.OverwriteWith` после пересчёта времени повторно отправляет клиенту пакет баффа с тем же индексом, чтобы UI получил новый таймер.

### Фикс сериализации Extend (2026-04-27)

**Проблема:** Клиент ArcheAge ожидает, что при `BuffStackRule.Extend` сервер отправляет **базовую длительность** баффа в `SCBuffCreatedPacket`, а не суммарную (оставшееся + новая). Сервер сам увеличивает `Duration` для внутреннего таймера, но в пакете шлёт исходное значение. Клиент, получая повторный пакет с базовой длительностью, сам прибавляет её к текущему отображаемому времени.

**Анализ официального трафика 5.0.7.0:** При 4 повторных кастах `20291 → 4841` каждый `SCBuffCreatedPacket` содержит `Duration/10 = 48000` (базовые 8 мин), `pish = 4`. Суммарная длительность нигде не передаётся.

**Решение:**
- Добавлено поле `Buff.BaseDuration` — базовая длительность с учётом модификаторов (без Extend-накопления).
- `Buffs.ApplyBuffDuration` сохраняет `BaseDuration = Duration` после применения модификаторов.
- `Buff.OverwriteWith` копирует `BaseDuration` от нового баффа.
- `Buff.WriteData` при `StackRule == Extend` или `ChargeExtend` отправляет `BaseDuration / 10` вместо `Duration / 10`.

**Файлы:**
- `AAEmu.Game/Models/Game/Skills/Buff.cs`
- `AAEmu.Game/Models/Game/Units/Buffs.cs`
- `AAEmu.UnitTests/Game/Models/Game/Skills/Helpers/BuffTestBuilder.cs`
- `AAEmu.UnitTests/Game/Models/Game/Skills/Tests/BuffStackingTests.cs`

Регрессионные тесты проверяют:

- `20291 -> buff 4841` существует и применим к `Slave`.
- `27032 -> buff 8335` существует и применим к `Slave`.
- `35166 -> buff 20584` остался рабочим.
- `27446 -> buff 11388` существует и применяется на родительский транспорт.
- У топливных mount skills для тракторов с описанием `달구지에 친환경 연료` не отсутствуют строки `BuffEffect`.
- `BuffStackRule.Extend` при повторном применении добавляет новую длительность к оставшемуся времени и отправляет обновление клиенту.
- `Buff.WriteData` для Extend-баффов отправляет базовую длительность (`BaseDuration`), а не суммарную (`Duration`).
